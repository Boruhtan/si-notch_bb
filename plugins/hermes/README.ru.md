# si-notch для Hermes

Плагин показывает удалённые сессии Hermes в чёлке Mac: задачу, видимые сообщения ассистента, начало/завершение/ошибки инструментов, итоговый ответ и отдельные профили в Agents.

Версия плагина **1.5**. Нужны **si-notch 0.4.9-beta.1 или новее**, доверенный вход по SSH с перенаправлением Unix-сокетов и Python 3.10+ на машине Hermes. Используются стандартная библиотека и существующий интерпретатор; дополнительные pip-пакеты, ключи моделей, TCP-сервер и служба не нужны.

## Рекомендуемый способ: настройки si-notch

1. На Mac установите si-notch. Для первой беты выберите **Settings → About → Beta** и обновитесь.
2. Откройте **Settings → Remote SSH → Add connection**, укажите имя и SSH-хост/alias. **Check connection** проверяет только вход.
3. Нажмите **Check profiles**, выберите профили, их отображаемые имена и разрешение на передачу текста.
4. **Preview changes → Apply plugin changes** устанавливает встроенные плагин и relay с резервными копиями. Проверьте результат; без запущенного gateway плагин загрузится при следующем запуске профиля.
5. Нажмите **Connect**. Успешная проверка входа не запускает туннель. Оставьте приложение и соединение работающими и начните новую задачу Hermes.
6. В **Sessions** раскройте карточку для истории инструментов. **Agents → имя подключения** показывает настроенные профили и без активной задачи.

Приложение устанавливает адаптер из своей сборки. Для установки с фиксированным Git SHA используйте альтернативу ниже и обновляйте код через Hermes. Повторное применение настроек приложения заменит адаптер встроенной версией; для каждого профиля выберите один способ обновления кода.

## Штатная установка через Hermes

Этот каталог — самостоятельный плагин с идентификатором `si-notch`. Встроенный `relay.py` запускается через Python и не требует исполняемого бита. Устанавливайте в профиль, где будут выполняться задачи, а не в проектный `.hermes`.

Возьмите проверенный полный SHA из [REVISION.md](REVISION.md):

```sh
hermes plugins install eugeneb1ack/si-notch/plugins/hermes --ref fb8396cb8a846d1f2c3b57228a5582a0450a9289 --no-enable
python3 "$HOME/.hermes/plugins/si-notch/configure.py" setup --name "Мой Hermes" --hide-text
hermes plugins enable si-notch
```

Команда использует полный проверенный SHA. Это установка из данного репозитория, а не запись каталога Hermes. Проверьте исходники и сохраните штатные проверки/согласования установщика. Для именованного профиля добавляйте `-p PROFILE` перед `plugins`; для `configure.py` используйте фактический home этого профиля. Если `python3` недоступен, используйте Python установленного Hermes.

`setup` меняет только собственный `si-notch.json`, создаёт приватный каталог сокета при необходимости и сохраняет предыдущие настройки перед изменением. Конфигурация Hermes, hooks, `.env`, модели, правила согласования и службы не редактируются. Активацией управляет штатная команда `plugins enable`. Если перезагрузка недоступна, после окончания текущего хода откройте новую сессию.

Передача текста: `--show-text` / `--hide-text`. Другой сокет: `--socket /absolute/private/events.sock`. Существующий helper сохраняется; `--bundled-relay` явно выбирает встроенный. Переменная `SI_NOTCH_CLI`, если задана, остаётся приоритетной и должна указывать на нужный исполняемый файл.

На Mac добавьте SSH-хост и **абсолютный путь сокета из результата setup**, затем нажмите **Connect**. **Check profiles** обнаружит параметры штатной установки; применение изменений приложения не обязательно и может заменить фиксированный код.

## Проверка

После подключения Mac:

```sh
python3 "$HOME/.hermes/plugins/si-notch/configure.py" check
```

`state: delivered` подтверждает приём события присутствия; задача не создаётся. Это ещё не проверка хода модели. Запустите [короткий тест](SMOKE_TEST_PROMPT.md) в новой сессии выбранного профиля. На Mac проверьте описание задачи, `Working · terminal`, два завершённых вызова в Activity, итоговый текст и Done. Повторите в другом профиле: карточки должны быть независимыми.

[Готовый промпт для установки](INSTALL_PROMPT.ru.md) · [English prompt](INSTALL_PROMPT.md). Агент выполняет удалённую часть, а отображение на Mac проверяется отдельно.

## Текст и поведение

При новой настройке передача текста выключена. После включения отправляются краткая задача (до 1600 символов), видимые промежуточные сообщения и итоговый ответ (до 4000 каждый). Промежуточные сообщения появляются, когда Hermes вызывает соответствующий hook; поток каждого токена не передаётся. Аргументы, результаты инструментов, история, скрытые рассуждения и credentials не отправляются. Для классификации ошибки локально читаются только флаги результата; содержание не передаётся. Activity хранит последние 12 записей приложения.

Идентификаторы хешируются; `instanceId` — стабильная идентичность профиля. Сохраняйте её при обновлении и меняйте при клонировании профиля на другую машину. Отображаемые имена — подписи в si-notch. Согласования остаются в Hermes; плагин лишь уведомляет об ожидании. При отключённом Mac доставка ограничена тайм-аутом, события не накапливаются и не воспроизводятся позднее.

## Диагностика

- **`not_connected`:** нажмите **Connect** на Mac и проверьте абсолютный путь. Проверка входа и работа туннеля — разные состояния.
- **`stale_socket` или ошибка forwarding 255 после перезапуска:** отключите это соединение на Mac, затем выполните предпросмотр и явное восстановление:

  ```sh
  python3 "$HOME/.hermes/plugins/si-notch/configure.py" repair-socket
  python3 "$HOME/.hermes/plugins/si-notch/configure.py" repair-socket --apply
  ```

  Восстановление требует `Connection refused`, правильного владельца/прав, отсутствия держателя в `lsof` и неизменного inode. Старый сокет сохраняется под резервным именем. Живой или занятый сокет не меняется. Без `lsof` изменений нет. Затем снова нажмите Connect и выполните check. Не удаляйте занятые сокеты и не включайте глобальный `StreamLocalBindUnlink`.
- **`relay_failed`:** проверьте ошибку, helper, путь сокета, запущенный и не приостановленный si-notch. Не ослабляйте проверку host key или права каталога.
- **Инструменты видны, сообщения нет:** разрешите текст в нужном профиле и начните новый ход. Если модель молчит или среда не вызывает hook промежуточного сообщения, будут только задача и финальный ответ.
- **Installed/Last seen:** профиль настроен, но свежего события нет. Туннель сам по себе не доказывает активность профиля.
- **Обновление и отключение:** выбирайте новый полный SHA явно, сохраняя `si-notch.json` и `instanceId`. `hermes plugins disable si-notch` отключает новые события после перезагрузки. SSH-туннель отключается отдельно. Не перезаписывайте установку из другого источника без проверки.

## Область проверки

На удалённом macOS с si-notch 0.4.9-beta.1 проверены три реальные API-сессии разных профилей, параллельная работа, по два последовательных terminal-вызова, задача/финальный текст и Done в живом интерфейсе. Автотесты проверяют приватность, hooks с `task_id`, ошибки инструментов, изоляцию профилей, доставку relay, повторную настройку, резервные копии и восстановление сокета. Linux, другие версии Hermes и все способы запуска требуют отдельного реального прогона.
