# Установка и обновление через Hermes-агента

Промпт подходит для локального Mac и удалённого SSH-хоста. Заполните поля один раз. Список профилей разрешает настройку только перечисленных профилей.

```text
Установи или обнови официальный наблюдающий плагин si-notch.
Расположение: <локальный Mac или удалённый SSH-хост/alias>
Существующие профили: <default, именованный профиль или явный список>
Имена в Чёлке: <отдельная подпись для каждого профиля>
Передавать текст задачи и сообщений ассистента: нет

Прочитай https://github.com/eugeneb1ack/si-notch/tree/v0.4.31/plugins/hermes/README.md и REVISION.md этого же релиза. Используй указанный там проверенный полный 40-символьный SHA кода. Не используй main, tag в --ref, другой репозиторий или старую закешированную инструкцию.

1. Проверь версию Hermes, plugins --help и фактический home каждого выбранного профиля. Устанавливай eugeneb1ack/si-notch/plugins/hermes штатным установщиком Hermes с --ref <проверенный полный SHA> --no-enable, указав -p PROFILE либо точный HERMES_HOME. Сохрани штатные проверки исходников и согласования. Не устанавливай заново Hermes, не меняй hooks, notify, модели, провайдеры и правила согласования, не читай credentials/истории и не перезапускай посторонние службы.

2. Если официальный плагин уже установлен, сохрани его собственные настройки и ожидающий usage-outbox вне каталога плагина. Сохрани происхождение, instanceId, пути socket/helper, разрешение на текст и неизвестные параметры. Обновляй на месте через поддерживаемый этой версией CLI путь смены закреплённого SHA, после проверки scan. Не удаляй плагин перед обновлением, не заменяй другой источник и не теряй локальные файлы. Если установленный CLI не умеет сохранить их, остановись на этой конкретной несовместимости. Плагин 1.12 совместим с новым приложением Mac; его можно оставить до безопасного обновления плагина.

3. Для каждого выбранного профиля отдельно запусти configure.py setup с его --name и приватным сокетом. Для нового профиля используй --hide-text, если я не разрешил текст. При обновлении не передавай параметры текста/helper/socket, если я не попросил их изменить. Сохраняй instanceId при каждом обновлении. У разных профилей, в том числе локальных, должны быть разные ID; имена могут совпадать. Не копируй si-notch.json и usage-outbox другого профиля. Только для явно выбранного нового клона со случайно скопированным ID используй setup --new-instance на этом клоне; исходный профиль не трогай и его ожидающий расход не переноси.

4. Для локального Mac достаточно запущенной Чёлки и её нативного si-notchctl. Стандартные каталоги приложения обнаруживаются автоматически; для нестандартного расположения задай --helper на Contents/Helpers/si-notchctl именно этого приложения. SSH и вторая служба агента не нужны. Для удалённого хоста внеси выданный абсолютный сокет в Настройки → Remote SSH и нажми Connect. Одно подключение обслуживает профили этого хоста; не создавай второй туннель к тому же endpoint и не меняй внутренние сокеты Mac.

5. Включи только si-notch выбранного профиля штатным CLI и проверь активацию. Если reload недоступен, заверши этот ход и открой новую сессию. Выполни configure.py check и дай до 30 секунд на heartbeat. Отдельно сообщи SHA, профиль/имя, версию плагина, резервную копию, активацию и доставку. Receipt подтверждает доставку, а не работу модели или интерфейс Mac. Проверь каждый профиль в Агентах независимо: отключение одного хоста не должно освежать остальные профили. Тест из SMOKE_TEST_PROMPT.md запускай только по моему поручению. Не согласовывай действия и не отправляй ответы за владельца.

Если сокета нет, запусти или подключи приложение. Для устаревшего сокета покажи repair-socket preview и получи разрешение перед --apply; не удаляй живой сокет и не ослабляй SSH-проверки. Задай один короткий вопрос только при отсутствии расположения, списка профилей, имён или действительно необходимого выбора. Посторонние профили не настраивай.
```
