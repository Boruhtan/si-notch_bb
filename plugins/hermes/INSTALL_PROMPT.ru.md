# Установка через Hermes-агента

Укажите профиль, отображаемое имя и разрешение на передачу текста. Этот промпт предназначен для Hermes **на удалённой машине**. Подключение и проверка интерфейса выполняются на вашем Mac.

```text
Установи наблюдающий плагин si-notch для этой машины Hermes.
Профиль: <default или явно выбранный существующий профиль>
Имя в si-notch: <отображаемое имя>
Передавать текст задачи и сообщений ассистента: нет

Источник: https://github.com/eugeneb1ack/si-notch/tree/main/plugins/hermes. Прочитай README и REVISION.md. Используй ровно проверенный полный Git SHA из REVISION.md; не устанавливай текущую вершину ветки или другой репозиторий.

Можно проверить версию и справку Hermes, фактический home выбранного профиля, метаданные плагина и путь приватного Unix-сокета. Не читай и не выводи .env, токены, пароли, SSH-ключи, историю, память и постороннюю конфигурацию. Сохрани существующие hooks, notify, модели, провайдеры и правила согласования. Не создавай credentials и постоянные службы. Если профиль, имя или выбор передачи текста не указаны, задай один короткий вопрос; не выбирай и не включай все профили самостоятельно.

Проверь исходники. Установи eugeneb1ack/si-notch/plugins/hermes штатной командой Hermes plugins install с --ref <проверенный полный SHA> --no-enable именно в выбранный профиль. Не обходи штатные проверки и согласования установщика. Если плагин уже установлен, сначала проверь происхождение и сохрани его настройки; не перезаписывай другую интеграцию.

Запусти установленный configure.py setup с выбранным именем, --hide-text, если я явно не разрешил текст, и нужным абсолютным путём приватного сокета. Сохрани стабильный instanceId и остальные параметры; запиши путь резервной копии. Затем включи только si-notch штатной командой Hermes выбранного профиля. Проверь фактический результат активации. Если текущий host не перезагружает плагин, попроси открыть новую сессию после этого хода. Не перезапускай другие службы и не подтверждай запросы за владельца.

Сообщи точный SSH-хост/alias и абсолютный путь сокета для Settings → Remote SSH в si-notch. Нужно нажать Connect: Check connection проверяет только вход. После моего подключения выполни configure.py check. Если сокета ещё нет, дождись подключения. Если он остался от старого туннеля, покажи repair-socket preview и получи разрешение перед --apply; сохраняй его под резервным именем. Не удаляй живой или занятый сокет и не ослабляй forwarding/проверку ключей.

После подтверждения доставки дай короткий тест из SMOKE_TEST_PROMPT.md для новой сессии. Выполняй его sleep/printf и видимые сообщения только по моему поручению. В отчёте отдельно укажи SHA источника, профиль, версию плагина, пути настроек/сокета/резервной копии, активацию и подтверждённую доставку. Успешная команда или completed run не доказывают отображение на Mac: попроси проверить текст задачи, историю инструментов, итоговый ответ и Done. Не утверждай, что всё проверено, если активация или интерфейс ещё неизвестны.
```
