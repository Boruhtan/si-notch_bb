# SSH-подключения

**Настройки → Remote SSH** поддерживает несколько подключений с независимыми именами. Добавьте подключение, задайте название и укажите SSH-хост или alias. Старые настройки одного хоста переносятся без автоматического подключения.

**Проверить соединение** проверяет вход по SSH с существующими ключами и `known_hosts`. Проверка не запускает туннель, не устанавливает файлы и не подтверждает разрешение перенаправления на сервере. **Подключить** запускает обратное перенаправление Unix-сокета, **Отключить** останавливает его. Перед изменением хоста или сокета нужно отключиться. Два активных подключения не могут использовать одинаковые хост и путь сокета.

В **Agents** подключения отображаются сворачиваемыми группами с профилями внутри. Имя можно менять в любой момент; флажок **Показывать в Agents** управляет видимостью группы. Удаление закрывает туннель и удаляет локальные настройки, но сохраняет удалённый плагин. Чтобы отключить его, сначала снимите отметки с профилей и примените изменения.

## Настройка профилей Hermes

1. Сначала настройте доверенный вход по SSH с ключом. Приложение не принимает неизвестные host keys и не запрашивает пароль.
2. Нажмите **Проверить профили**. Проверка использует существующее окружение Python Hermes и возвращает имена профилей и метаданные плагина. Секреты, переписка и содержимое конфигурации не передаются.
3. Выберите профили, задайте отображаемые имена и при необходимости включите **Показывать задачу и сообщения ассистента**. Для нестандартной установки доступны дополнительные пути.
4. Нажмите **Просмотреть изменения**, проверьте список профилей и количество файлов и настроек, затем **Применить изменения плагина**. Изменение выбора или удалённой конфигурации требует нового предпросмотра. Резервные копии остаются на удалённой машине; результат показывает их каталог.
5. Укажите полученный при проверке абсолютный путь сокета и нажмите **Подключить**. Если плагин настроен раньше подключения, свежие события появятся со следующим ходом профиля.

Установка добавляет встроенный плагин и relay, сохраняет остальные настройки и hooks и просит Hermes перезагрузить плагины. Если gateway профиля не запущен, плагин загрузится при следующем запуске. После прерывания установки нужно снова проверить профили; изменения не повторяются вслепую.

Профили видны и без активных задач. Online означает недавнее событие, а не подтверждение работы молчащего процесса. Поднятый SSH-туннель сам по себе не доказывает активность профиля.

## События и текст

Плагин передаёт состояние сессии, названия инструментов, начало, завершение и ошибки вызовов, ожидание ответа. Текст включается отдельно и содержит краткое описание задачи, видимые промежуточные сообщения и итоговый ответ. При новой настройке передача текста выключена. Описание задачи ограничено 1600 символами, сообщение и ответ — 4000. Аргументы, результаты инструментов, история переписки и скрытые рассуждения не передаются. События согласования служат уведомлениями; плагин ничего не подтверждает за пользователя.

Идентификаторы профилей и сессий хешируются для разделения профилей и хостов. Группы и отображаемые имена определяются локальными настройками. Раскройте карточку сессии, чтобы увидеть историю, включая завершённые вызовы инструментов.

## Другие удалённые агенты

Установите `scripts/remote-relay.py` как `~/.local/bin/si-notchctl` с правами 0700. Создайте `~/.si-notch/run` с правами 0700, укажите абсолютный путь сокета в приложении. В окружении агента:

```sh
export SI_NOTCH_SOCKET="$HOME/.si-notch/run/events.sock"
export SI_NOTCH_CLI="$HOME/.local/bin/si-notchctl"
"$SI_NOTCH_CLI" emit '{"event":"agent.working","session_id":"remote-test","provider":"custom","title":"Remote test"}'
```

Подключайте только доверенные учётные записи: они могут отправлять события и запросы решения. Существующий сокет не заменяется. При ошибке проверьте вход по SSH, host key, разрешение forwarding и занятость сокета. Выход из приложения останавливает все его туннели. [Область проверки](parity.md).
