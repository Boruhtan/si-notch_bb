# Подключение агентов

Откройте **Настройки → Подключение → Сканировать**, выберите агента и проверьте параметры подключения. Сканирование проверяет приложения, пути исполняемых файлов и типовые каталоги менеджеров версий. Оно не запускает и не устанавливает агентов.

**Адаптер настроен** означает, что файлы готовы. **События получены** подтверждает доставку от агента. После подключения начните новую сессию; открытой сессии может понадобиться перезагрузка.

## Переход к сессии

Нажмите на карточку, чтобы открыть задачу Codex или исходный терминал/редактор. Стрелка раскрывает подробности. После перехода остров остаётся открытым до ухода курсора. Локальный helper определяет Ghostty, Terminal, iTerm, VS Code, Cursor, WezTerm, Warp и Zed по окружению вызывающего процесса. Переход активирует приложение; конкретная вкладка терминала не выбирается. У сессии, обнаруженной только по файлу, адрес приложения может отсутствовать до первого события адаптера.

Своей интеграции можно передать `terminal_bundle_id` (например, `com.mitchellh.ghostty`) или `target_url`. Поддержаны `codex://threads/<UUID>` и ссылки на локальные файлы VS Code, Cursor и Zed. Ссылки для запуска команд и расширений отклоняются. Для событий SSH локальный терминал автоматически не определяется.

## Codex и Pi

Сессии Codex Desktop обнаруживаются автоматически через локальный IPC; CLI-сессии — также по локальным журналам. **Подключить Codex** добавляет и разрешает восемь встроенных CLI hooks после проверки их содержимого. Существующие hooks и `notify` сохраняются. Если авторизация не прошла, проверьте записи через `/hooks` в Codex CLI. Протокол Desktop может измениться с обновлением Codex.

Для обнаружения локального Desktop-чата не требуется сообщение о reasoning в логе. Возобновлённые CLI-сессии находятся и в старых папках дат через нативные файловые события; активные файлы продолжают опрашиваться. Ограничения в восемь подписок Desktop и шестнадцать rollout-файлов сняты. Открытие завершённой истории Desktop само по себе не создаёт карточку задачи. Полностью локальный Work использует ту же интеграцию; объём живой проверки указан в [статусе функций](parity.md). Облачные Work и dots эта интеграция не поддерживает.

На карточках локального Work отображается **Work** со значком портфеля. У Codex сохраняются название и значок кода. Режим определяется по нативным метаданным: упоминание Work в запросе или заголовке не меняет бейдж. Новый обнаруженный ход может восстановить разговор после выхода предыдущего CLI-процесса.

**Подключить Pi** регистрирует встроенное расширение в `~/.pi/agent/settings.json`. Выполните `/reload` в открытой сессии или перезапустите Pi.

## Claude Code, Gemini CLI, Copilot CLI и Cursor

Нажмите **Подключить**, чтобы добавить встроенный адаптер в конфигурацию ниже. Существующие настройки и hooks сохраняются; рядом с изменённым файлом создаётся резервная копия. Некорректный JSON, отключённые hooks и конфликтующие старые адаптеры требуют ручной проверки. Python для этих интеграций не нужен.

| Агент | Настройки пользователя |
| --- | --- |
| Claude Code | `~/.claude/settings.json` |
| Gemini CLI | `~/.gemini/settings.json` |
| Copilot CLI | `~/.copilot/hooks/si-notch.json` |
| Cursor | `~/.cursor/hooks.json` |

Разрешения остаются в агенте. Необязательный [обработчик разрешений Claude](claude-permissions.md) настраивается отдельно. Политики организации и доверие к проекту могут блокировать hooks; si-notch их не переопределяет.

## OpenCode и Hermes

**Подключить OpenCode** копирует встроенный плагин в `~/.config/opencode/plugins/`. Перезапустите OpenCode. Если плагин уже установлен в каталоге проекта, удалите эту копию перед использованием глобального плагина.

**Подключить Hermes** копирует встроенный плагин в `~/.hermes/plugins/si-notch/`. Включите его в Hermes, затем перезапустите сессию:

```sh
hermes plugins enable si-notch
```

Оба плагина сохраняют абсолютный путь установленного helper, включая нестандартное расположение приложения. Копии, установленные вручную, также проверяют `/Applications` и `~/Applications`. Переменная `SI_NOTCH_CLI` позволяет задать другой путь.

Приложение учитывает абсолютные `CLAUDE_CONFIG_DIR`, `COPILOT_HOME`, `XDG_CONFIG_HOME` и `HERMES_HOME` из своего окружения. Finder не наследует настройки оболочки терминала. При нестандартном каталоге или профиле Hermes проверьте показанный путь и при необходимости настройте профиль отдельно.

## Свой API и удалённые агенты

Свою интеграцию можно подключить через [JSON API](architecture.md), отправляя события сессии. Для агентов на другом хосте используется [SSH-ретранслятор](remote-connections.md).

Если сессия не появилась, перезагрузите адаптер, начните новый ход и откройте **Настройки → Диагностика**. Указанный там helper позволяет проверить доставку:

```sh
/Applications/si-notch.app/Contents/Helpers/si-notchctl status
```
