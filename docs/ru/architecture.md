# Локальный API

Встроенный helper отправляет JSON в `~/.si-notch/run/events.sock`. Используйте постоянный `session_id` и имя своего агента в `provider`.

```sh
~/Applications/si-notch.app/Contents/Helpers/si-notchctl emit \
  '{"event":"agent.working","session_id":"my-task","provider":"custom","title":"Check build","message":"Running tests"}'
```

Основные события: `session.start`, `agent.working`, `agent.waiting`, `agent.completed`, `agent.failed`, `session.end`, `tool.start`, `tool.finish`. Дополнительные поля: `title`, `message`, `cwd`, `tool_name`, `model`, `id`, `sequence`. Уникальные ID событий и порядковые номера защищают от дублей и запоздалых обновлений. Передавайте одинаковый `turn_id` из разных наблюдателей одного хода, чтобы исключить повторные звуки; следующий ход должен иметь новый ID. Допустимые поля определены в [AgentEvent.swift](../../Sources/SINotchCore/AgentEvent.swift).

## Решения

```sh
~/Applications/si-notch.app/Contents/Helpers/si-notchctl request \
  '{"session_id":"my-task","provider":"custom","message":"Allow this action?"}' --timeout 60
```

`request` ждёт ответ только на текущий запрос. Коды выхода: **0** — разрешение/ответ, **1** — отказ, **2** — неверные данные, тайм-аут или разрыв связи. Вызывающий агент должен сам исполнить решение. si-notch не выполняет запрошенное действие.

## Транспорт и код

- Размер JSON — до 128 КиБ; `emit` ждёт подтверждение до одной секунды.
- Права сокета и каталога — 0600 и 0700, доступ только тому же пользователю. Поддерживаются до 16 клиентов и восьми ожидающих запросов.
- Другой сокет задаётся через `SI_NOTCH_SOCKET` или `--socket /absolute/path`.
- `SINotchCore` — состояния и разбор событий; `SINotchTransport` — IPC; `SINotch` — AppKit/SwiftUI и наблюдение за агентами.
- Текущие состояния сессий хранятся в памяти. Отдельный локальный архив текстов переживает очистку готовых карточек и перезапуск; настройки — в UserDefaults.

Другие команды: `si-notchctl --help` — `run`, `hook`, `notify`, `paths`, `status`.

## Доступность агентов

В Sessions отображаются задачи: работа, ожидание, разрешение, завершение и ошибка. Подключённые агенты без задачи и записи Codex без контекста показываются только в Agents. Несколько сессий одного провайдера имеют одну строку подключения. Online означает запущенное приложение или событие за последние две минуты; более старые данные отмечаются «Был на связи». Установка сама по себе не означает подключение.

Сессии Codex с источником `internal` или `subagent` исключаются из списка задач. Свои и неопределённые источники остаются доступными. Клиент API может пометить служебную сессию полем `is_internal_session`, в том числе после первых событий.

## Локальная история

История — последний фильтр Sessions после All, Working, Attention и Done. Он доступен и без текущих карточек. Запись объединяет один запрос/ход, ответы агента и доступные тексты команд. Тексты поступают из локального Desktop, файлов Codex и Pi. Для остальных интеграций сохраняются только уже передаваемые тексты: настройка не включает обмен содержимым удалённых сессий и не восстанавливает отсутствующие команды. Вывод инструментов, рассуждения, вложения и данные запросов разрешений исключены. Старые переписки не импортируются.

Файлы JSON и небольшой индекс метаданных находятся в `~/Library/Application Support/si-notch/History` с правами 0700/0600. Все операции выполняются в последовательной фоновой очереди. Список показывает по 50 записей; содержимое читается при открытии, в кеше остаются до восьми записей. Фонового опроса архива нет. Изменения записываются с объединением до двух секунд, завершение запроса и обычный выход сохраняют буфер.

По умолчанию — 1 000 записей и 200 МиБ вместе с индексом. Можно задать от 1 до 10 000 записей и от 1 до 2 048 МиБ; при превышении любого лимита удаляются старейшие записи. Индекс дополнительно ограничен 4 МиБ. Один текст ограничен 16 384 символами, запись — 256 КиБ; длинные записи сохраняют запрос и последние тексты с отметкой о сокращении. Поиск работает по заголовкам запросов, проектам и провайдерам. Очистка отменяет отложенные записи и защищает от поздних снимков очищенных ходов. Отключение записи сохраняет существующий архив. Типовые токены и пароли скрываются; личные данные в тексте всё ещё возможны.

Свой источник может передавать `history_items`: массив объектов `{ "id": "stable-item-id", "role": "user|assistant|command", "text": "public text" }`. Используйте постоянные ID текстов для обновления потока и новый `turn_id` для запроса. Допускаются до 64 элементов и 128 КиБ их текста в пределах общего лимита транспорта. Не передавайте вывод команд или произвольные словари аргументов.

Пошаговая реализация, таблицы полей и запускаемые изолированные проверки — в [руководстве своего агента](custom-agents.md).
